Purpose:

Pipeline flow:

```text
OpenCV BGR frame or image path
  -> input validation
  -> grayscale/BGRA safety conversion to BGR
  -> existing preprocessing
  -> existing bright candidate detector
  -> existing patch crop logic from prepare_patches.py
  -> CNN classification
  -> CNN/CV fused candidate ranking
  -> stable output dictionary
  -> annotated diagnostic image
```

Important boundary:

Phase 6 is single-frame only. It does not implement Kalman tracking, temporal verification, PID control, API communication, or Unity communication yet.

```yaml
pipeline:
  target_id: Terminal_B
  crop_size: 40
  patch_size: 32
  device: auto
  fusion:
    cnn_weight: 0.80
    cv_weight: 0.20
```

The fusion weights are validated and must sum to `1.0`.

## Design Decisions

The classifier checkpoint is loaded once when `SingleFramePipeline` is created. It is not reloaded per candidate or frame.

Candidate crops reuse:

```text
prepare_patches.crop_with_padding()
```

This keeps inference crop behavior compatible with CNN training.

The BGR crop is converted to RGB before tensor normalization, matching the training path where saved BGR patches were loaded and converted to RGB.

All valid candidates are kept. The pipeline records these values for every candidate:

```text
correct_probability
false_probability
predicted_class
cnn_confidence
cv_baseline_score
fused_score
```

Candidate ranking uses:

```text
fused_score = 0.80 * correct_probability + 0.20 * baseline_score
```

The accepted target must satisfy:

```text
correct_probability >= confidence_threshold
```

The starting threshold remains:

```text
0.55
```

The actual `result.json` also includes frame width/height, selected bounding box, inference time, and the full per-candidate list.

For not-found cases, the same top-level keys are preserved where practical and the status is one of:

```text
no_candidates
below_confidence_threshold
```

## Coordinate Convention

Image error:

```text
image_error_x_px = target_x - frame_center_x
image_error_y_px = target_y - frame_center_y
```

Image-space meaning:

```text
Right = positive X
Left = negative X
Down = positive Y
Up = negative Y
```

Control error:

```text
control_error_x = image_error_x_px / frame_center_x
control_error_y = -image_error_y_px / frame_center_y
```

Control-space meaning:

```text
Right = positive pan
Left = negative pan
Up = positive tilt
Down = negative tilt
```

Normalized control errors are clamped to:

```text
[-1, 1]
```
